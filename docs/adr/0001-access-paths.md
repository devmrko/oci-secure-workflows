# 관리 접속과 서비스 진입점을 분리한다

날짜: 2026-11-22. 상태: 로컬 도구의 설계 결정. 실제 테넌시 구성 확정과 별개입니다.

## 배경

대상 용도는 SSH 개발·관리와 웹/API 서비스의 혼합입니다. Public IP 제거 후에도 두 접속 경로를 유지해야 합니다.

## 결정

사람의 임시 관리 접속은 OCI 관리형 Bastion을 사용합니다. 고정 TCP 포워딩과 SOCKS5를 하나의 JSON 설정 기반 CLI로 제공합니다. 매번 새 세션을 생성해 대상·키·남은 TTL의 불일치를 피하고 자동 갱신은 제공하지 않습니다.

상시 서비스는 LB 또는 API Gateway로 분리합니다. 환경마다 다른 기존 네트워크를 스크립트로 덮어쓰지 않도록 Terraform 계획과 적용을 분리하고, NAT 라우트 테이블은 생성까지만 담당합니다. backend NSG의 VNIC 연결도 명시적 별도 단계로 둡니다.

## 결과

개발 도구와 상시 서비스가 Bastion 세션 수명에 함께 묶이지 않습니다. 대신 TLS·DNS·backend NSG·기존 라우팅의 명시적 연결 작업이 필요합니다. Bastion을 하루 종일 사용하는 불편은 회사 사설망 연결이나 VCN 내부 실행기로 해결할 수 있습니다.

대형 landing zone 모듈이나 자체 점프 VM은 현재의 접속 전환 범위를 넘는 네트워크·운영 자원을 추가하므로 채택하지 않았습니다. 외부 참고 코드를 복사하지 않고 공식 서비스 인터페이스에 맞춰 구현합니다.
